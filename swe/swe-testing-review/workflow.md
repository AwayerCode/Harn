# 测试审查

## 目标

交付风险覆盖、断言有效性、替身边界、执行接入和验证证据的审查结果；违规与缺口也构成有效交付。

审查的完成是覆盖与证据说明完整，违规也可交付；不要求修复所有问题。

## 规则

### 文件写入边界（强制）

本 Skill 只做 Review，禁止新增、修改、删除、移动或重命名任何文件，包括设计、源码、测试、配置、快照、报告、日志与缓存。只能读取已有产物并在回复中交付结论，不自动修正，也不在 Review 中调用其他 Skill 执行修改。

检查命令必须确定无文件写入、副作用或自动修复。文档校验使用 Python `-B` 禁用字节码缓存；测试、构建、格式化和代码生成若会写文件就不得执行，说明未执行及原因。不能通过先写后删除、临时副本或事后恢复绕过只读边界。

发现问题时仅说明证据、位置、影响与建议归属。即使任务同时要求修复，也先完成并结束 Review，再切换到相应 Design 或 Implementation Skill；该 Skill 自行检查输入和写入范围，Review 不承担修复。

### 职责与判定要求

检查测试能否证明已确认的业务与设计要求，并通过适用的实际执行核验结果。审查包括测试设计、现有测试代码、执行接入及运行证据；用户明确只要求静态审查时不运行测试。

不修改任何文件，不创建测试设计或补写测试。发现问题时明确文件位置、需求依据、风险、复现场景和需要补充的证据；修正交给结束 Review 后的独立设计或实施环节。


### 只读结果核对

执行前取得共享脚本的文件指纹并保存在执行上下文，不生成基线文件。结束或因输入缺口提前退出前，比较原指纹。发生变化时停止后续检查，报告变化与归因未确认，不自动回退或重新记录基线。无 Git 环境或无法取得指纹时明确只读核对未验证，仍可做有依据的静态审查。

### 检查要求与执行

静态审查和实际运行分支分别完成；无法只读运行时审查已有证据并说明未执行，不以绿色测试或覆盖率替代风险与断言审查。

| 检查执行 | 作用与条件 |
|---|---|
| [本模块格式规则](references/document-format.md)与 [validate_documents.py](scripts/validate_documents.py) | 检查必要输入及本模块设计产物的格式和引用；不证明专业内容或运行行为正确 |
| [check_scope.py](../scripts/check_scope.py) | 核对实际写入范围或只读结果；Python 3 标准库和 Git，属于规则的检查执行，不是业务资源 |
| 内容审查、项目检查与实际验证 | 按下面保留的专业要求和完成标准确认内容与行为；涉及运行先确认工具、环境、权限、输出位置和副作用 |

检查执行、范围覆盖、退出码及失败处理统一遵守[执行规范](../references/standards/execution.md)。


## 资源

| 资源 | 用途与条件 |
|---|---|
| 用户目标、共同约定、任务范围与验收要求 | 决定本轮应交付或审查的内容，不替代专业依据 |
| 测试设计、已有测试代码和入口、已有执行证据及按场景需要的业务、系统、协议与交互依据 | 按下方输入规则定位权威位置和条件性依据，缺少关键内容时停止依赖它的操作 |
| 已有项目工具、环境及历史证据 | 按当前风险选择实际检查；历史通过不代表当前通过，副作用或环境不明时先核实 |

输入按用户路径、项目索引和实际引用定位，只读取当前相关部分。资源不足明确影响；未确认的业务规则不由实现、测试或界面补造。


## 路径

### 执行前范围核对

先确认对象、比较基线、实施阶段与适用风险，然后在其他检查前记录只读指纹：

```bash
python3 -B <SWE目录>/scripts/check_scope.py readonly --root <目标Git根目录>
```

将输出 `sha256` 保存在执行上下文；后续输入检查失败也必须在交付前完成结束核对。

### 执行前文档检查

业务模型及其他文档格式统一由[共同产物规范](../references/standards/artifacts.md)维护。按声明的输入类型使用共享校验器，仅读取相关专业依据，不要求加载生产方工作流。

缺失或不合格的必需文档仍阻止执行。

必需输入：测试设计文档和当前范围已有的测试代码、执行入口或验证证据。根据测试设计的实际引用及当前检查的规则读取业务模型、系统设计、接口协议或交互规范；这些是对应场景的条件性依据，不要求无关文档全部齐备。测试尚未落地时，可指出相对设计的缺口，不自行编写测试。

查找权威文档，核对测试设计、现有测试及实现的对应关系。必需文档缺失、格式不合格或无法支撑当前审查时停止，不自行补建设计。缺少运行环境时可继续已有证据支持的静态审查，但执行结果标为未执行或阻塞，不以静态检查代替运行结论。

先按用户给定路径、项目文档索引和相关引用定位文件，再按对应类型运行格式校验。多个候选来源无法确认权威位置时停止并说明，不任意选取。已通过格式检查仍需核对当前范围和关键语义；存在阻断项时不开始本 Skill 的实际执行。

使用本 Skill 的实际安装路径执行以下命令，条件性文档仅在上述条件成立时检查，`<文档路径>` 替换为实际文件：

```bash
python3 -B <SWE目录>/scripts/validate_documents.py --kind business-model --file <文档路径>
python3 -B <本 Skill 目录>/scripts/validate_documents.py --kind system-design --file <文档路径>
python3 -B <本 Skill 目录>/scripts/validate_documents.py --kind interface-protocol --file <文档路径>
python3 -B <本 Skill 目录>/scripts/validate_documents.py --kind interaction-standards --file <文档路径>
python3 -B <本 Skill 目录>/scripts/validate_documents.py --kind test-design --file <文档路径>
```

缺失和不合格的输入只作为阻塞反馈；本 Skill 不修复职责外输入或调用其他 Skill 越界修改，需要纠正时先结束当前环节，再进入对应 Skill。所需输入已存在且合格时直接执行当前任务，不额外请求确认。

审查单位是风险、测试场景、断言与执行证据。读取实现只为判断测试能否暴露缺陷，不扩展为全面代码逻辑审查；执行项目已有测试不等于编写或实现测试。

### 审查方法

1. 将业务规则、状态变化、公共协议和适用交互规范映射到测试设计与实际场景，检查重要风险及禁止副作用是否遗漏。
2. 检查断言是否验证公开行为和业务结果，能否在相应缺陷发生时失败；不把复制实现算法、只断言替身调用或空测试当作行为证据。
3. 检查正常、拒绝、未知结果、部分成功、重复操作、中断和迟到结果的适用覆盖；异步时序可控制，等待有超时。
4. 检查替身是否保留协议关键语义、数据是否隔离、基线变化是否有独立依据，区分模拟通过与真实集成证据。
5. 核对测试发现、构建、运行和清理入口，检查实际执行是否覆盖声称的范围；不得仅凭测试数量或覆盖率认定充分。
6. 按当前风险运行相关检查，对比设计预期与实际观察，归类产品缺陷、测试缺陷、设计缺口和环境限制。

测试设计本身也是审查对象，格式通过不证明场景或预期正确。设计与业务依据冲突时明确指出，不以当前实现或已有绿色测试覆盖业务规则。

### 环境与执行

只运行经确认不写任何文件、不修改业务数据且无外部副作用的已有测试。不准备或重置数据，不启动会产生文件或改变业务状态的服务，不更新快照，不落盘缓存、日志与报告。无法保证只读时不执行，说明环境限制和未验证范围。

依次执行当前变化所需的检查。通过后，只有新增变化、失败或未解决风险才扩大或重复测试；不能以反复运行全量测试代替问题定位。

涉及持久任务时审查已有重启、竞争、幂等和确认场景及对应证据；需要写入数据或故障注入的验证不在 Review 内执行，只指出所缺证据。

涉及 UI 时审查已有操作场景与证据，只执行已确认无写入或业务副作用的操作；截图用于视觉证据，不能独自证明操作可用。浏览器验证不自动证明其他平台、真机设备或外部服务能力。

### 结果与诊断

分别记录实际执行的命令或操作、环境、通过和失败及覆盖边界。历史成功记录不能作为当前通过结果。

区分产品缺陷、测试错误和环境限制。失败时保留足够的复现信息；修正由后续 Design 或 Implementation 完成；再次 Review 时只读复查受影响范围。不能跳过失败、弱化断言或伪造依赖成功来宣布完成。

明确证据的限度：类型与构建不证明业务正确；模块替身不证明真实链路；模拟模型不证明模型质量；一个平台通过不证明另一个平台可用。

### 交付与完成标准

在回复中交付按影响排序的发现、文件位置、依据、复现场景、建议归属、实际执行命令、结果与证据边界。没有发现时说明审查范围及剩余风险；未执行、失败或阻塞明确列出，不生成独立测试报告。

完成意味着已审查约定范围并明确证据与缺口，不要求为交付结论消除所有缺陷。绿色测试不自动代表产品验收完成。

本 Skill 声明所需输入类型并引用共同 schema 与共享校验器；业务模型的专业语义按对应建模规则审查。Review 不提交、推送、部署或回写外部系统。

### 结束核对与覆盖确认

```bash
python3 -B <SWE目录>/scripts/check_scope.py readonly --root <原Git根目录> --expected <原sha256>
```

逐项核对本轮适用对象和风险：已检查项有依据及证据，待确认项有缺失信息，未检查项有原因。不适用有明确理由。审查发现问题无需修复或重跑到全绿；运行失败只说明相应验证状态，不能直接当成产品缺陷。结论限于实际覆盖，不能据此宣布产品整体完成。

收尾前确认结果与实际证据一致，简述检查、未覆盖项和阻塞，不默认生成报告。提交、推送或对外回写遵循用户授权。
