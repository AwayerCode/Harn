# 代码实现

## 目标

交付符合设计与协议的业务和技术代码、必要工程接入及实际验证结果，保留必要行为并清理被替代实现。

完成需同时满足本模块专业标准、实际检查和范围核对；关键缺口影响哪些目标要明确，不以格式通过代替语义或行为正确。

## 规则

### 文件写入边界（强制）

本 Skill 只做 Implementation，只能修改当前实现范围内的业务与技术模块源码、必要非 UI 运行资源、工程配置、依赖清单与代码生成产物。UI 页面、组件、样式及展示资源由 swe-ui-impl 负责，本 Skill 只读。测试代码、替身、测试数据和测试配置由 swe-testing-impl 负责，本 Skill 只读。所有文档只读，包括业务模型、系统设计、接口协议、交互规范、测试设计、README 与协作说明；不得新增、修改、删除或移动文档。

执行前从系统设计的代码结构映射和项目约定明确允许写入的目录与文件，例如源码目录、运行资源目录，以及逐项列出的构建配置与依赖文件。例子不作为全局路径模板；目录职责不明或文档与代码混放时确定具体文件清单，不用扩展名、全仓通配或工作区权限替代约定。

生成命令与测试也遵守此边界；会改文档或写入范围外文件的命令不得执行。交付前核对本次实际改动均属于允许范围，区分用户已有改动，发现越界立即停止并报告，不回退用户改动。

设计缺失、矛盾或实现需要改变已确认规则时停止受影响实施，只在回复中说明缺口。结束 Implementation 后由对应 Design 修订，依据合格后重新进入实施，不能边实现边改文档以取得通过。

### 职责与判定要求

把需求与设计落实为可靠、可维护的代码。读取相关业务规则、设计与协议、现有代码、工程约定和验收条件；检查真实调用者、构建与运行入口，不默认加载整个项目。

简单修复也先检查所需设计与协议。缺少状态归属、确认语义、权限规则或依赖提供者等关键设计时停止实施并反馈，不凭实现便利改变业务行为。


### 模块与运行边界

- 模块提供稳定、完整的公共能力，消费者遵守项目定义的入口，不访问私有实现或通过转发绕过边界。
- 业务类型、转换与规则跟随所属模块；公共工具只承载真正无业务归属的能力。
- 应用组装创建、连接、启动和释放实例；业务执行顺序、保存队列与恢复策略属于对应业务模块。
- 模块导入不隐式启动请求、设备、定时器或后台任务。真实资源在明确的运行入口创建。
- 共享输入和快照按需隔离可修改引用；静态 `readonly` 不提供运行时引用隔离。
- 后端授权与事务位于业务规定的边界内；UI 或传输层检查不能替代业务授权。
- 沿用适合项目的架构与技术栈，不因套用 Skill 引入固定分层、仓储模式或额外基础设施。

### 异步执行与生命周期

存在异步、并发或共享状态时，按实际风险检查：

- 结果返回前核对身份、上下文、生命周期与必要的版本；迟到结果不能写入失效状态或新会话。
- 保存期间产生的新修改仍有处理路径；只清理已确认版本。版本 A 的回执不能覆盖后续 B、清除 B 的脏状态或触发已失效导航。
- 区分未发出、明确拒绝、未知结果、远端确认和本地交付失败。按协议恢复，不以无条件重试、空值或假成功掩盖异常。
- 重试具备适用性依据、次数或时间边界；有副作用动作遵守幂等与确认机制。
- 页面释放使用权、销毁共享实例和取消服务端业务是不同动作，由各自所有者处理。
- 资源、订阅、监听器和定时器有明确清理入口；取消后迟到的工作不能继续推进业务。

持久任务按设计落实重启恢复、多实例竞争和重复执行控制；不把进程内状态当作持久事实。

### 重构与契约变化

业务结构调整与行为调整按风险组织批次，不强制固定阶段。兼容层必须有真实消费者与退出条件，不能长期保留两套权威实现。

移动源码时检查路径别名、路由、静态资源、平台预处理、生成代码、测试与部署引用。已确认接口的代码变化同步提供方与实际消费者；如果需要改变设计或协议，先停止并反馈。生成流程只能更新允许范围内的代码产物，不能改文档。

### 写入结果核对

执行前按既有职责固定可写文件、职责独立目录和允许的运行产物目录，保留用户已有改动。混合目录细化到文件，共用配置还要人工核对具体条目；目录或文件允许不表示其中任意业务均可修改。

将共享脚本基线保存在目标项目外的全新临时文件，固定允许范围，不能用 HEAD 差异代替。检查新增、修改和删除；越界时停止，不自动回退用户修改，不修改契约、扩大范围或重建基线消除报错。若不能建立基线，停止写入并说明范围核对缺失，不静默略过。

### 检查要求与执行

高风险修改需要行为保护证据。必要证据尚未建立时停止受影响重构，结束本环节后交测试实施补齐，不先改代码再声称受保护。

| 检查执行 | 作用与条件 |
|---|---|
| [本模块格式规则](references/document-format.md)与 [validate_documents.py](scripts/validate_documents.py) | 检查必要输入及本模块设计产物的格式和引用；不证明专业内容或运行行为正确 |
| [check_scope.py](../scripts/check_scope.py) | 核对实际写入范围或只读结果；Python 3 标准库和 Git，属于规则的检查执行，不是业务资源 |
| 内容审查、项目检查与实际验证 | 按下面保留的专业要求和完成标准确认内容与行为；涉及运行先确认工具、环境、权限、输出位置和副作用 |

所有 Python 命令使用 `-B`。共享检查随 SWE 包提供，不复制到目标项目；模块不需要其他阶段先执行，但依赖明确列出的包内检查。脚本退出码 0 为本次检查通过，1 为发现问题，2 为无法检查；没有实际执行、失败或无法运行均不能说通过。相同检查问题连续三次未解决时停止重试，报告缺口和所需决策，不反复运行直到偶然通过。

范围检查覆盖 Git 跟踪及非忽略文件的最终内容、类型和权限；写入检查还覆盖明确允许文件与运行目录中的忽略文件。未列明的忽略文件、`.git`、项目外文件或改后恢复的动作不在覆盖范围，也不提供权限隔离。这些对象仍受本模块行为边界约束。不得修改原基线来掩盖变化；保留用户已有修改，无法确定变化归因时明确说明。

## 路径

### 执行前范围核对

先确认任务、权威输入和实际可写文件，在首次写入前固定范围：

```bash
python3 -B <SWE目录>/scripts/check_scope.py snapshot --root <目标Git根目录> --baseline <项目外全新临时文件> --allow-file <允许文件相对路径>
```

多个文件重复 `--allow-file`；只有明确职责独立的目录才可用 `--allow-dir`。运行产物也要事先限定；混合源码目录和整个仓库不能当作可写范围。默认只维护自己负责的产物，不因为检查失败修正其他模块产物。

### 执行前文档检查

格式校验使用本目录内的规范、契约与脚本，文档格式使用自身契约，基本检查使用 SWE 包内共享脚本。上游输入以文档产物衔接，产出该文档的 Skill 无需安装；缺失或不合格的必需文档仍阻止执行。

必需输入：系统设计文档和接口协议文档；UI 和测试代码分别由独立的 swe-ui-impl 与 swe-testing-impl 实施。所有输入文档只读。

查找两份权威文档，读取模块职责、代码映射、依赖、状态归属及具体公共协议，并通过其中的引用读取相关业务模型。任一必需文档缺失、格式不合格或无法支撑当前实现时停止，不根据代码猜测设计、不自动创建或修订上游设计。

先按用户给定路径、项目文档索引和相关引用定位文件，再按对应类型运行格式校验。多个候选来源无法确认权威位置时停止并说明，不任意选取。已通过格式检查仍需核对当前范围和关键语义；存在阻断项时不开始本 Skill 的实际执行。

使用本 Skill 的实际安装路径执行以下命令，条件性文档仅在上述条件成立时检查，`<文档路径>` 替换为实际文件：

```bash
python3 -B <本 Skill 目录>/scripts/validate_documents.py --kind system-design --file <文档路径>
python3 -B <本 Skill 目录>/scripts/validate_documents.py --kind interface-protocol --file <文档路径>
```

缺失和不合格的输入只作为阻塞反馈；本 Skill 不修复职责外输入或调用其他 Skill 越界修改，需要纠正时先结束当前环节，再进入对应 Skill。所需输入已存在且合格时直接执行当前任务，不额外请求确认。

### 工作方法

1. 确认目标行为、允许变化及必须保护的现有行为，定位根因或主要实现路径。
2. 根据风险选择验证证据。高风险重构先建立行为保护；低影响改动使用已有检查和直接验证。需要新增或调整测试时反馈给独立测试实施环节，不在本 Skill 内修改测试。
3. 落实公共入口、数据模型与协议，再实现内部逻辑、依赖组装和调用者接入。按可审查、可验证的范围推进。
4. 沿真实业务路径核对数据、控制流、副作用与结果返回，不以文件移动或类型通过代替行为正确。
5. 清理被替代的入口、重复模型、绕行转发、失效配置与引用；同步构建、生成产物、资源和部署消费路径。
6. 执行适用检查，核对代码与设计一致，报告实际结果及未覆盖范围。

### 交付与完成标准

交付实现代码、必要的机器接口与工程文件、旧实现清理及验证结果。说明剩余问题、环境限制和未验证能力；提交、推送与部署遵循当前任务授权。

完成时检查：目标行为符合需求；公共能力与依赖符合设计；必要业务行为得到保护；资源正确释放；旧入口与失效引用已处理；没有用绕过边界或伪造结果取得表面通过。

### 产物约定

交付业务与技术模块代码及必要工程文件和代码生成产物，不修改设计或其他文档，不生成独立执行报告。实际修改、验证结果、未覆盖范围与阻塞在回复或已有任务记录中说明。所需设计文档使用本 Skill 保存的输入契约只读校验；发现文档需要更新时停止相应实施并反馈。代码通过目标项目工具和行为验证检查。

### 结束核对与覆盖确认

```bash
python3 -B <SWE目录>/scripts/check_scope.py check --root <原Git根目录> --baseline <原临时基线文件>
```

格式或本模块产物错误在允许范围内修正后，重新执行相关检查和范围核对；内容审查产生新改动时同样重查。上游缺口、越界、生产缺陷或环境阻塞按职责反馈，不以弱化检查取得通过。

每项本轮目标对应产物和检查结果，必要能力未验证时明确限制，不能把“代码或文档已写完”当作已验收。修改范围核对还需人工确认允许文件内的职责与共用配置条目。

收尾前确认结果与实际证据一致，简述检查、未覆盖项和阻塞，不默认生成报告。提交、推送或对外回写遵循用户授权。
