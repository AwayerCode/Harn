# UI 设计

## 目标

交付交互规范，使实施者明确布局、用户路径、公共能力、状态反馈、恢复行为和目标平台验收预期。

完成需同时满足本模块专业标准、实际检查和范围核对；关键缺口影响哪些目标要明确，不以格式通过代替语义或行为正确。

## 规则

遵守[按需加载与职责边界](../references/standards/loading.md)，按当前对象读取共同标准与项目契约；不加载其他专业工作流来完成本职责。

### 文件写入边界（强制）

本 Skill 只做 Design，只能新增或修改本 Skill 所负责的设计文档；不能修改任何源码、测试代码、样式、配置、依赖清单、资源或生成产物，也不能顺带更新其他类型的设计文档。

执行前根据用户路径、项目约定和权威文档确认允许写入的准确文件清单。新项目默认位置：`design/interaction-standards/interaction-standards.md`。已有项目使用已确认的设计目录及权威文件位置；不靠扩展名判断，不扩大到整个仓库或所有 Markdown 文档，路径归属有歧义时停止相关写入。

只读参考其他文档与代码。检查工具不能修改代码、配置或生成文件；Python 校验使用 `-B`，避免缓存写入。交付前核对本次实际改动均属于上述清单，区分用户已有改动，发现越界立即停止并报告，不回退用户改动。

需要改代码时在回复中说明实施要求，结束 Design 后由 Implementation 执行；需要改其他设计时交给对应 Design，本 Skill 不跨职责补建或修订。

### 职责与判定要求

让用户理解当前状态、完成操作并知道下一步。只制定或更新交互规范，UI 代码由 swe-ui-impl 实施。

缺少业务能力或恢复协议时停止相关设计并反馈，不自行创造权限、确认机制或服务端能力。


### 状态与职责

- 页面拥有显示、输入、弹窗、焦点与导航状态；业务事实、确认、保存队列及跨动作流程由对应业务模块拥有。
- 查询失败不能呈现为成功空列表，未知结果不能显示为明确失败并开放无条件重试。
- 上传、转写、分析等分别呈现真实阶段，局部完成不能显示为整体完成。
- 按钮只承诺协议实际支持的动作。隐藏面板、停止安排、处理在途请求、取消和放弃分别表达。
- 提交旧版本后继续编辑，新版本的内容和未保存状态不能被旧回执覆盖；导航服从当前有效意图。
- 业务顺序、展示序号和实体标识分别处理；显示格式不能改变业务规则。
- 产品文案使用用户理解的状态与动作，不暴露内部修订、代次、依赖注入等实现术语。

### 写入结果核对

遵守[共同执行规范](../references/standards/execution.md#范围与授权)，使用包内 `scripts/check_scope.py` 固定本次范围并核对实际改动。

### 检查要求与执行

操作只能承诺协议支持的能力，界面状态与业务事实区分；不通过写代码制作原型。

| 检查执行 | 作用与条件 |
|---|---|
| [本模块格式规则](references/document-format.md)与 [validate_documents.py](scripts/validate_documents.py) | 检查必要输入及本模块设计产物的格式和引用；不证明专业内容或运行行为正确 |
| [check_scope.py](../scripts/check_scope.py) | 核对实际写入范围或只读结果；Python 3 标准库和 Git，属于规则的检查执行，不是业务资源 |
| [check_artifacts.py](../scripts/check_artifacts.py) | 根据本模块产物检查显式对应关系；用法及未覆盖语义见下文，Python 3 标准库，只读 |
| 内容审查、项目检查与实际验证 | 按下面保留的专业要求和完成标准确认内容与行为；涉及运行先确认工具、环境、权限、输出位置和副作用 |

检查执行、范围覆盖、退出码及失败处理统一遵守[执行规范](../references/standards/execution.md)。


### 操作与协议对应检查

仅有 `界面:动作` 或明确不适用的业务映射时可省略 `--protocol`；存在业务操作时必须提供协议依据。

公共能力列优先使用 `协议:标识`；已有能力名称能唯一对应协议索引时直接识别。纯界面动作可用 `界面:动作`，其是否真的不依赖业务由内容审查判断，不虚构业务协议。无法唯一识别的自然语言表达标为未验证，人工核对，不强制改写整个项目。

显式引用检查完整标识，不截取有效前缀。标识使用字母、数字、点、下划线或连字符；多个引用以空格、顿号、逗号或分号分隔，可用反引号包裹。例如 `协议:save/不存在` 是非法引用，不能按 `协议:save` 通过；非法、空或悬空引用报错，不列入已检查通过项。

```bash
python3 -B <SWE目录>/scripts/check_artifacts.py --kind ui --file <交互规范路径> --protocol <接口协议路径>
```

脚本执行本模块文档格式校验、重复协议标识和悬空能力引用检查；可见状态、异常恢复和验收场景是否正确仍需内容审查。完成内容调整后重跑。

## 资源

| 资源 | 用途与条件 |
|---|---|
| 用户目标、共同约定、任务范围与验收要求 | 决定本轮应交付或审查的内容，不替代专业依据 |
| 系统设计、接口协议、用户任务、目标平台、现有交互规范、界面证据及品牌参考 | 按下方输入规则定位权威位置和条件性依据，缺少关键内容时停止依赖它的操作 |

输入按用户路径、项目索引和实际引用定位，只读取当前相关部分。资源不足明确影响；未确认的业务规则不由实现、测试或界面补造。

### 输入与现状

读取用户目标、业务规则、系统设计、公共协议、目标平台、现有界面和必要视觉参考。保留项目已有品牌与交互惯例，除非任务明确要求改变。

## 路径

### 执行前范围核对

先确认任务、权威输入和实际可写文件，在首次写入前固定范围：

```bash
python3 -B <SWE目录>/scripts/check_scope.py snapshot --root <目标Git根目录> --baseline <项目外全新临时文件> --allow-file <允许文件相对路径>
```

多个文件重复 `--allow-file`；只有明确职责独立的目录才可用 `--allow-dir`。运行产物也要事先限定；混合源码目录和整个仓库不能当作可写范围。默认只维护自己负责的产物，不因为检查失败修正其他模块产物。

### 执行前文档检查

格式校验使用本目录内的规范、契约与脚本，文档格式使用共同 schema，基本检查使用 SWE 包内共享脚本。上游输入以文档产物衔接，产出该文档的 Skill 无需安装；缺失或不合格的必需文档仍阻止执行。

必需输入：已确认的用户任务、目标平台和交互要求；修改已有规范时读取现有交互规范。涉及系统边界时读取系统设计，涉及业务调用和状态时读取接口协议；纯视觉与界面局部任务不要求无关业务文档。

涉及业务时查找权威设计与协议，从公开能力和状态语义确定 UI 的业务依据；纯界面动作明确使用 `界面:动作`。仅在任务明确要求制定交互规范时，该规范作为本 Skill 的产物创建；不实现 UI 或修改页面、组件、主题和样式。任一必需文档缺失、格式不合格或关键能力未确定时停止，不在 UI 中补造业务设计。

先按用户给定路径、项目文档索引和相关引用定位文件，再按对应类型运行格式校验。多个候选来源无法确认权威位置时停止并说明，不任意选取。已通过格式检查仍需核对当前范围和关键语义；存在阻断项时不开始本 Skill 的实际执行。

使用本 Skill 的实际安装路径执行以下命令，条件性文档仅在上述条件成立时检查，`<文档路径>` 替换为实际文件：

```bash
python3 -B <本 Skill 目录>/scripts/validate_documents.py --kind system-design --file <文档路径>
python3 -B <本 Skill 目录>/scripts/validate_documents.py --kind interface-protocol --file <文档路径>
python3 -B <本 Skill 目录>/scripts/validate_documents.py --kind interaction-standards --file <文档路径>
```

缺失和不合格的输入只作为阻塞反馈；本 Skill 不修复职责外输入或调用其他 Skill 越界修改，需要纠正时先结束当前环节，再进入对应 Skill。所需输入已存在且合格时直接执行当前任务，不额外请求确认。

### 制定交互规范

1. 明确用户角色、任务、入口、上下文和完成条件。
2. 组织信息层级、页面关系、主要与次要操作，定义导航、返回和上下文保留。
3. 建立“用户触发 → 业务调用 → 可见状态 → 反馈 → 后续可操作行为”的对应关系。
4. 覆盖实际适用的加载、成功无数据、正常内容、校验错误、处理中、明确失败、部分完成、未知结果和恢复。
5. 定义颜色、字体、间距、布局、控件状态、文案、键盘与触控规则，优先复用现有设计系统。
6. 选择代表性页面验证规范；以真实长度、错误内容和操作检验布局，再扩展共性规则。

规范描述可执行行为和验收条件，不只列视觉参数。规模较小的变化可以局部说明，不强制建立完整设计系统或全量页面样板。

### 设计完成标准

在规范中定义组件协作、页面路径、主题与布局规则、输入和状态反馈，以及目标平台验收条件。可只读分析已有界面和证据，不通过修改代码制作原型或执行产生文件与业务变化的操作。

交付应使实施者明确布局、行为、状态、异常恢复和验收预期。只交付交互规范；UI 实现与真实操作验证由后续 swe-ui-impl 和 swe-ui-review 承担，设计推演不宣称已完成运行验收。

### 产物契约与格式校验

唯一文件产物是交互规范，必要说明写入回复；不生成 UI 代码、执行报告或其他文档。

- `interaction-standards`：交互规范，默认位置 `design/interaction-standards/interaction-standards.md`；使用 [模板](assets/interaction-standards.md)。

遵守[本 Skill 文档规则](references/document-format.md)和[本 Skill 的机器契约](references/artifact-contract.json)。实际文档必须有完整必需章节，表格字段和判定值必须符合契约；模板占位符必须替换，不适用项写明原因。

校验命令使用本 Skill 的实际安装路径执行，`--file` 可以指向任意目标项目，工具不绑定项目路径：

```bash
python3 -B <本 Skill 目录>/scripts/validate_documents.py --kind interaction-standards --file <文档路径>
```

交付前校验本 Skill 负责的设计产物并修正其格式错误；其他文档只读校验，缺口反馈归属，不跨范围修改。每次实际修改与执行记录在回复或已有任务记录中说明，长期设计不维护任务进度。文档校验通过只证明约定格式与局部引用成立，不证明业务、设计或运行行为正确；继续执行该 Skill 的语义检查和对应验证。

### 产物对应关系检查

交付前必须执行“规则”中对应关系检查的命令，核对 `errors`、`checked` 和 `unverified`。发现错误时修正本模块产物并重跑；对未自动检查的自然语言关系逐项人工核对，不能把脚本退出码 0 当作全部内容通过。

### 结束核对与覆盖确认

```bash
python3 -B <SWE目录>/scripts/check_scope.py check --root <原Git根目录> --baseline <原临时基线文件>
```

格式或本模块产物错误在允许范围内修正后，重新执行相关检查和范围核对；内容审查产生新改动时同样重查。上游缺口、越界、生产缺陷或环境阻塞按职责反馈，不以弱化检查取得通过。

每项本轮目标对应产物和检查结果，必要能力未验证时明确限制，不能把“代码或文档已写完”当作已验收。修改范围核对还需人工确认允许文件内的职责与共用配置条目。

收尾前确认结果与实际证据一致，简述检查、未覆盖项和阻塞，不默认生成报告。提交、推送或对外回写遵循用户授权。
