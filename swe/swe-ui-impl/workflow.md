# UI 实施

## 目标

交付符合交互规范的界面代码、展示资源和必要界面配置，真实操作、状态与公共能力接入有相应验证。

完成需同时满足本模块专业标准、实际检查和范围核对；关键缺口影响哪些目标要明确，不以格式通过代替语义或行为正确。

## 规则

### 文件写入边界（强制）

本 Skill 只做交互 Implementation。只允许修改当前范围的页面、组件、布局、主题、样式、展示资源、界面状态代码及必要界面路由或构建配置；业务模型与规则、服务、持久化、公共协议代码和测试均只读。所有文档只读，不新增、修改、删除或移动设计及其他文档。

执行前依据系统设计的文件映射、交互规范和项目约定明确允许写入的目录及文件。UI 与业务代码混放时按实际职责确定文件清单，不能因为一个目录含 UI 就把整个目录列为可写。共用配置仅修改明确属于本次界面接入的条目，不改变业务协议、权限或测试行为。

构建、预览和平台验证只能在明确的实现与运行产物范围内写入，不生成报告文档，不修改设计、测试或业务文件。交付前核对本次实际改动，区分并保护用户已有修改；发现越界停止并报告。

设计缺失、公共能力不足或业务实现有缺陷时反馈对应归属，不在界面代码中补造业务规则、不修改业务模块，不在本 Skill 内调用越界修正。结束当前实施后由对应环节纠正，再依据合格输入继续。

### UI 实现

通过公共能力连接业务，通用组件通过输入、事件及组合接口协作，不内置业务实例或权限规则。

主题、样式、页面和展示资源按照项目职责组织，不强制框架或目录模板。先解决代表性的列表、表单、弹层或长任务共性问题，再推广到相关消费者；不靠逐页复制维持一致性。

保留筛选、分页、顺序和返回上下文；直接进入详情或编辑页时提供明确返回路径。有未保存内容时统一处理取消、返回和导航，恢复后保留输入及有效焦点。

富文本预览与保存后展示采用一致安全规则，并保留允许的有效格式。无障碍语义、可见标签和错误关联与控件行为一起实现。

从截图提取规律时区分观察、推断与设计决定，不从图片像素直接断定 CSS 尺寸、字体或交互行为。

### 平台验证

按目标平台和变化风险验证，不要求每次执行所有专项：

- 桌面：键盘操作、焦点进入与恢复、弹层与 Escape 层级、错误定位、缩放和溢出。
- 移动：安全区、软键盘、固定底栏、滚动末尾、触控和设备权限。
- 特定平台：组件注册、编译分支、媒体、导航和权限，在对应构建与运行环境验证。
- 业务路径：主要操作、重复操作保护、加载与错误反馈、离开与返回、失败恢复。

视觉检查与操作验证分别给出结论。源码、构建或截图不能替代真实交互；一个平台的验证不能证明其他平台可用。

### 写入结果核对

执行前按既有职责固定可写文件、职责独立目录和允许的运行产物目录，保留用户已有改动。混合目录细化到文件，共用配置还要人工核对具体条目；目录或文件允许不表示其中任意业务均可修改。

将共享脚本基线保存在目标项目外的全新临时文件，固定允许范围，不能用 HEAD 差异代替。检查新增、修改和删除；越界时停止，不自动回退用户修改，不修改契约、扩大范围或重建基线消除报错。若不能建立基线，停止写入并说明范围核对缺失，不静默略过。

### 检查要求与执行

生产代码中只允许修改本次 UI 职责；业务与技术模块代码、测试及全部文档只读。缺少目标平台环境时区分已实现与未验证，不把截图当作操作通过。

| 检查执行 | 作用与条件 |
|---|---|
| [本模块格式规则](references/document-format.md)与 [validate_documents.py](scripts/validate_documents.py) | 检查必要输入及本模块设计产物的格式和引用；不证明专业内容或运行行为正确 |
| [check_scope.py](../scripts/check_scope.py) | 核对实际写入范围或只读结果；Python 3 标准库和 Git，属于规则的检查执行，不是业务资源 |
| 内容审查、项目检查与实际验证 | 按下面保留的专业要求和完成标准确认内容与行为；涉及运行先确认工具、环境、权限、输出位置和副作用 |

所有 Python 命令使用 `-B`。共享检查随 SWE 包提供，不复制到目标项目；模块不需要其他阶段先执行，但依赖明确列出的包内检查。脚本退出码 0 为本次检查通过，1 为发现问题，2 为无法检查；没有实际执行、失败或无法运行均不能说通过。相同检查问题连续三次未解决时停止重试，报告缺口和所需决策，不反复运行直到偶然通过。

范围检查覆盖 Git 跟踪及非忽略文件的最终内容、类型和权限；写入检查还覆盖明确允许文件与运行目录中的忽略文件。未列明的忽略文件、`.git`、项目外文件或改后恢复的动作不在覆盖范围，也不提供权限隔离。这些对象仍受本模块行为边界约束。不得修改原基线来掩盖变化；保留用户已有修改，无法确定变化归因时明确说明。


## 资源

| 资源 | 用途与条件 |
|---|---|
| 用户目标、共同约定、任务范围与验收要求 | 决定本轮应交付或审查的内容，不替代专业依据 |
| 交互规范、系统设计、接口协议、现有组件主题、目标平台及可用运行和操作环境 | 按下方输入规则定位权威位置和条件性依据，缺少关键内容时停止依赖它的操作 |
| 已有项目工具、环境及历史证据 | 按当前风险选择实际检查；历史通过不代表当前通过，副作用或环境不明时先核实 |

输入按用户路径、项目索引和实际引用定位，只读取当前相关部分。资源不足明确影响；未确认的业务规则不由实现、测试或界面补造。


## 路径

### 执行前范围核对

先确认任务、权威输入和实际可写文件，在首次写入前固定范围：

```bash
python3 -B <SWE目录>/scripts/check_scope.py snapshot --root <目标Git根目录> --baseline <项目外全新临时文件> --allow-file <允许文件相对路径>
```

多个文件重复 `--allow-file`；只有明确职责独立的目录才可用 `--allow-dir`。运行产物也要事先限定；混合源码目录和整个仓库不能当作可写范围。默认只维护自己负责的产物，不因为检查失败修正其他模块产物。

### 执行前文档检查

必需输入：交互规范、系统设计与接口协议。定位目标项目的权威文件，读取页面与组件职责、用户路径、状态语义、公共能力及目标平台验收条件；文档缺失、格式不合格或关键行为未明确时停止。

本 Skill 使用自身[输入契约](references/input-contract.json)、[校验规则](references/document-format.md)与脚本，不要求运行其他阶段；基本检查使用 SWE 包内共享脚本，不修改输入文档。

```bash
python3 -B <本 Skill 目录>/scripts/validate_documents.py --kind interaction-standards --file <文档路径>
python3 -B <本 Skill 目录>/scripts/validate_documents.py --kind system-design --file <文档路径>
python3 -B <本 Skill 目录>/scripts/validate_documents.py --kind interface-protocol --file <文档路径>
```

### 工作方法

1. 将规范中的操作、页面关系、可见状态和反馈映射到界面文件，确认允许写入的范围。
2. 复用既有主题和组件，通过约定公开能力连接业务，不从页面访问私有实现或复制业务规则。
3. 落实导航、上下文保留、输入、加载、空数据、失败、未知结果和恢复，以及适用的无障碍行为。
4. 按目标平台运行必要构建和实际操作验证，区分视觉、操作和业务链路证据。
5. 清理本范围被替代的 UI 入口、资源和引用，复查直接消费者。需要新增测试交给测试实施。

### 交付与完成标准

交付界面代码、展示资源和必要界面配置，结果直接回复，不创建或更新文档、测试代码或业务代码。说明实际平台、操作、验证结果、未覆盖范围与阻塞，不以截图或构建通过代替操作可用。

约定界面能表达真实业务状态、公开能力接入正确、上下文与输入得到保持、操作和反馈符合交互规范后完成。后续 Review 读取规范及实际 UI 即可，不依赖安装本 Skill。提交与推送遵循用户授权。

### 结束核对与覆盖确认

```bash
python3 -B <SWE目录>/scripts/check_scope.py check --root <原Git根目录> --baseline <原临时基线文件>
```

格式或本模块产物错误在允许范围内修正后，重新执行相关检查和范围核对；内容审查产生新改动时同样重查。上游缺口、越界、生产缺陷或环境阻塞按职责反馈，不以弱化检查取得通过。

每项本轮目标对应产物和检查结果，必要能力未验证时明确限制，不能把“代码或文档已写完”当作已验收。修改范围核对还需人工确认允许文件内的职责与共用配置条目。

收尾前确认结果与实际证据一致，简述检查、未覆盖项和阻塞，不默认生成报告。提交、推送或对外回写遵循用户授权。
