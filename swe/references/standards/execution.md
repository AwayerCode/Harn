# 执行与检查规范

## 范围与授权

执行前确认本次模块、可写文件和职责独立目录，共用配置细化到条目。混合目录与整个仓库不能作为默认可写范围。保留用户已有改动，构建、测试和生成命令产生的文件也必须在允许范围内。

首次写入前固定允许范围，将全新基线保存在项目外临时目录；不得用 HEAD 差异替代，不得覆盖、重建基线或扩大范围消除违规：

```bash
python3 -B <SWE目录>/scripts/check_scope.py snapshot --root <目标Git根目录> --baseline <项目外全新临时文件> --allow-file <允许文件相对路径>
python3 -B <SWE目录>/scripts/check_scope.py check --root <原Git根目录> --baseline <原临时文件>
```

多个文件重复 `--allow-file`，明确职责独立的目录可用 `--allow-dir`。检查无法建立时停止写入；越界先停止并报告，不回退用户修改。共享文档还需人工核对本次可写章节，文件级检查不能证明章节未越界。

Review 只读，使用 `check_scope.py readonly --root <Git根目录>` 保存输出 sha256 到执行上下文，结束时加 `--expected <原sha256>` 复查。不能执行会写缓存、日志、报告、数据或其他文件的命令，不通过先写后删绕过边界。

## 检查边界

范围检查覆盖 Git 跟踪和非忽略文件、明确允许路径中的忽略产物，以及子模块引用、检出版本与可检查文件。不覆盖其他忽略文件、`.git`、项目外文件或执行中改后恢复的动作，不提供权限隔离；这些对象仍不能越界修改。

父仓库允许范围不能跨入子模块；需要修改时在子模块 Git 根目录单独建立基线。未初始化子模块记录状态，不自动初始化或拉取。共享 Git 命令最多等待 10 秒；超时、读取或仓库错误按无法检查处理，不忽略失败。

Python 使用 `-B` 避免缓存。检查器退出码 0 为本次检查通过，1 为违规，2 为无法检查；缺失或未运行不能说通过。相同问题连续三次无法修正时停止重复尝试，报告原因和所需决策。

格式校验验证表达，架构与内容审查验证责任和依赖，行为与集成测试验证运行承诺。每项关键约束明确对象、依据、方法和失败处理；不以字段非空、格式通过、测试数量或历史结果证明整体正确。

## 协作与交付

实现者不修改标准或已确认契约来迁就实现，验收者不降低预期。必要变更反馈对应标准或设计责任方，由人确认；不阻止依据充分的无关工作。

实现任务可以修改事先明确的本模块单元测试，断言来自契约；跨模块和独立验收测试归测试实施。同一测试文件只指定一个维护责任方。修改测试不能删减既定要求。

交付区分通过、失败、未执行与阻塞，说明真实产物、命令、环境、证据和覆盖边界，不默认生成报告文件。提交、推送、部署、发布和外部通信遵循用户授权。
