# 审查输入文档校验

本 Skill 只读取目标项目已有的权威文档，不保存项目文档副本、产物模板或示例文档。输入类型及格式由本目录的 `input-contract.json` 定义，使用自身 `scripts/validate_documents.py` 校验。只读核对复用 [SWE 共享检查](../../scripts/check_scope.py)，不依赖其他阶段先执行；子模块处理见 [SWE 改动范围](../../SKILL.md#改动范围)。

必需文档与条件性文档以 [workflow.md](../workflow.md) 为准。通过用户路径、项目文档索引和实际引用定位文件；不能以历史对话或现有代码替代设计依据。文档缺失、格式错误、依据冲突或无法支撑范围时停止相关审查并说明，不创建或改写文档。

校验检查一级标题、完整且有序的二级章节、必要内容、表格字段与非空数据、文档元信息、协议字段、模板占位符、代码围栏和本地引用。文档状态为草案、待验收或已验收，不能替代任务状态；占位符必须替换。章节不适用时保留标题并填写“不适用：”及具体原因，文档信息不能省略。

使用本 Skill 的实际安装路径执行：

```bash
python3 -B <本 Skill 目录>/scripts/validate_documents.py --kind <输入类型> --file <目标项目文档路径>
```

退出码 0 表示格式合格，1 表示文档违规，2 表示读取或参数错误。格式合格不代表规则正确或实现符合规则；仍须按本 Skill 的对象与粒度审查。

禁止写入任何文件；只执行无写入的检查，不创建样本、缓存或报告。审查结论在回复中交付，说明依据、位置、偏离、影响、实际验证和未覆盖范围，不生成独立报告。格式契约随本 Skill 独立维护，变更不能用于迁就错误输入。

## 结构检查的表达与结果

`check_structure.py` 读取系统设计的“代码结构映射”，接受新格式“设计责任、代码位置、公开入口、依赖约束”和旧格式“设计责任、代码位置、公共入口、约束”。未包含映射的兼容文档仍可通过格式校验，但结构脚本会报告依据缺口，不从代码反推设计。

可自动检查的代码位置与入口使用项目根目录相对路径，可用反引号包围。公开入口文件使用完整相对路径，不将其解释为模块目录相对路径；符号名、通配符、多位置说明和其他自然语言表达标为未验证，由人工核对，不要求改写既有设计。无公开入口填写“无”。路径不能越出项目根目录，指向外部的符号链接不自动跟随检查。

同一路径映射多项责任或入口位于模块位置之外，报告待确认的映射缺口，不能在未了解共享规则时直接判错。声明位置缺失作为事实输出，是否违规取决于本轮实施阶段。脚本不解析公开导出的内容、源码依赖、别名、路由或运行行为，需继续完成相应审查。

标准输出包含 `checked`（本次检查对象）、`findings`（观察到的结构问题）、`gaps`（依据缺口）、`unverified`（未自动检查范围）。退出码 0 表示脚本本次检查无问题或缺口，1 表示发现问题或缺口，2 表示无法运行；任何代码都不代表全部结构审查完成。

`check_readonly.py` 的指纹输出仅保存在执行上下文中，比较前后 Git 跟踪及非忽略文件的内容、类型和权限，包含子模块引用、检出版本及其可检查文件。它不记录到文件、不输出文件内容，不证明没有发生改后恢复的写入，也不能将其他人的并发改动归因给 Agent。
