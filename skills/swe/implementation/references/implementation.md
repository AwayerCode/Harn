# 模块实现与质量

## 兑现契约

按设计的输入、输出、错误、副作用和时序语义实现公开能力。边界值、异常输入与部分失败有确定结果，业务不变量由代码保证，不依赖调用者了解内部实现。契约所需测试证据由测试领域维护，代码实现只读取和运行已有测试。

## 内聚与能力集成

按业务概念和变化原因组织模块内部代码，判断一次业务变化能否在模块内完成、无关变化是否迫使模块修改。内部复杂度用组件处理，不凭代码量拆分业务模块；只为稳定概念和真实变化增加抽象。

设计决定复用、采购或自研边界，实现遵守已确认协议接入外部能力。集中第三方类型、失败转换、连接与替换逻辑，使策略不散落在框架回调中。依赖数量不是质量标准，必要性、方向和影响范围才是。

## 状态、资源与失败

沿创建、使用、取消、失败和销毁路径核对所有权，遵守共享[实现运行约束](../../references/standards/implementation.md)。纯计算不强行引入生命周期；有状态模块明确合法转换、同步边界和晚到结果处理。超时与结果未知不能等同失败，日志和错误须支持恢复决策。

运行组装在明确入口创建、连接、启动与关闭对象，不承载业务决策，不在模块导入时启动设备、线程或任务。部署环境与发布流程由部署领域维护。

## 重构与性能

重构前确认真实消费者、行为基线和受影响入口，必要测试证据缺失时交测试领域补齐；不同时更改契约和实现以隐藏回归。移动代码同步检查导入、配置、路由、资源与生成入口，删除无消费者的兼容层。测试移动与改写由测试领域处理。

性能优化先定位实际瓶颈、负载与可观察指标，再比较改动收益和复杂度成本；不凭猜测增加缓存、并发或间接层。基准与压力测试由测试领域维护，结果不能跨环境扩大解释。
