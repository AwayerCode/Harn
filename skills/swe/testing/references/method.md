# 风险、测试与证据

## 测试设计

1. 从用户路径、状态转换、公共协议和历史失败提取重要风险。
2. 为每个风险确定场景、前置条件、输入、操作、预期结果与禁止发生的副作用。
3. 选择能够证明该风险的层级：静态检查、单元、模块协作、集成、HTTP、浏览器、目标平台或真实外部服务。
4. 明确替身边界、数据隔离、运行环境、观察方式与不可证明的部分。
5. 高风险重构先冻结外部行为基线；异步协作优先构造请求顺序、身份变化、版本变化和生命周期场景。

不要求每个任务覆盖所有层级。可逆、低影响变化优先使用已有检查和直接验证；新增测试应保护有价值的行为。

## 测试实现

1. 对照测试设计建立风险、场景、断言与测试入口的映射，按当前任务范围实施，不自选新的业务预期。
2. 复用项目运行器，编写测试和必要替身，落实数据隔离、可控时序、观察与清理。
3. 接入实际执行入口，运行针对性的测试，确认场景能验证设计约束；不靠编译成功、测试数量或覆盖率代替行为证据。
4. 区分生产缺陷、测试实现错误、设计缺口和环境限制；只修复本范围的测试实现错误。
5. 复查失败场景与修改影响。通过后只因新变化、失败或剩余风险扩大验证。

## 测试审查

1. 将业务规则、状态变化、公共协议和适用交互规范映射到测试设计与实际场景，检查重要风险及禁止副作用是否遗漏。
2. 检查断言是否验证公开行为和业务结果，能否在相应缺陷发生时失败；不把复制实现算法、只断言替身调用或空测试当作行为证据。
3. 检查正常、拒绝、未知结果、部分成功、重复操作、中断和迟到结果的适用覆盖；异步时序可控制，等待有超时。
4. 检查替身是否保留协议关键语义、数据是否隔离、基线变化是否有独立依据，区分模拟通过与真实集成证据。
5. 核对测试发现、构建、运行和清理入口，检查实际执行是否覆盖声称的范围；不得仅凭测试数量或覆盖率认定充分。
6. 按当前风险运行相关检查，对比设计预期与实际观察，归类产品缺陷、测试缺陷、设计缺口和环境限制。

测试设计本身也是审查对象，格式通过不证明场景或预期正确。设计与业务依据冲突时明确指出，不以当前实现或已有绿色测试覆盖业务规则。

## 执行证据

选择能够直接观察目标风险的最小范围，按失败代价组合单元、集成、端到端、性能、安全与兼容证据，不规定固定测试比例。类型与构建不证明业务正确，模块替身不证明真实链路，模拟模型不证明模型质量，一个平台通过不证明其他平台可用。

执行前明确隔离数据、运行环境、观察点、超时和清理方式。持久任务验证重启、竞争、幂等和确认；外部依赖需要真实协作证据，替身明确无法证明的部分。区分生产缺陷、测试错误、设计缺口和环境限制。结果记录命令、环境、当前观察及覆盖边界，不默认生成报告文件。

证据可以作为阻断门禁、非阻断信号或人工复核依据，按风险和置信度选择，不能因能够自动化就全部阻断。预期变更必须有业务或设计依据，不跳过失败、不弱化断言、不伪造依赖成功。
