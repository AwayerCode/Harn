# 项目接入

adoption 属于 SWE，随整个包安装、更新和登记版本，共用包内 CLI。它组织项目接入与生命周期维护，不是第六个专业领域，也不要求依次执行五个领域。由 [SWE 总入口](../SKILL.md)显式加载。

## 职责与改动范围

遵守[领域边界](../references/standards/domains.md)和[执行规范](../references/standards/execution.md)，先确定目标目录、已有权威依据、可写文件或配置条目及验证范围。接入可以只覆盖一个应用，不等于接管整个 monorepo。

adoption 维护项目接入记录、必要的 Agent 指引引用和检查入口的接线条目。宿主已经发现 SWE 时不重复写入 AGENTS。共享配置按条目编辑，保留已有内容和并行修改；安装 Skill 不自动授权重构、重写测试、发布或部署。

| 需要处理的产物 | 按需使用的能力 |
| --- | --- |
| 业务事实、实体和规则存在缺口 | [业务模型](../business-model/SKILL.md) |
| YAML 建立、修订和生成视图 | [系统设计](../system-design/SKILL.md) |
| 生产代码及其文件迁移 | [代码实现](../implementation/SKILL.md) |
| 所有测试及测试配置 | [测试](../testing/SKILL.md) |
| CI/CD 发布配置、部署及交付验证 | [发布交付](../delivery/SKILL.md) |

目录迁移按文件职责拆分：生产文件归代码实现，测试、夹具和快照归测试，YAML 与设计文档归系统设计，部署文件归发布交付。先列出源文件、目标路径和所有者，再分别建立范围；不得用整个混合目录的移动授权代替各领域文件清单。

跨领域工作以任务已有授权为准，明确切换能力与写入范围。接线不改变测试断言、架构规则或发布策略；遇到这些变化交由对应领域处理。

## 选择操作

1. 首次接入或为已有代码建立／修订 YAML：读取[已有项目与 YAML](references/existing-project.md)。已有 YAML 默认保留为权威依据，不从当前代码覆盖重建。
2. 更新 SWE 或退出项目：读取[更新与退出](references/lifecycle.md)。工具生命周期与项目产物生命周期分开处理。
3. 工具定位、版本绑定、命令和结果：复用 [CLI 约定](../references/cli.md)。harn 只分发所选资源；swe-cli 检查已编码规则；Agent 作专业判断；项目工具验证行为。本能力不提供自动生成器、候选设计预演或新的 CLI 命令。

## 完成证据

在项目现有约定位置维护最小接入记录：所选范围与未覆盖目录、YAML 位置、SWE 版本和 CLI 版本、接线条目的文件位置及用途、原有值与本次变化、验证结果和未验证项、退出时保留与移除的对象。记录使用项目相对路径，不保存凭据或个人机器路径；不复制架构内容、共享规范或安装数据库。

明确区分工具已安装、设计已建立、实现检查通过和行为验证通过。失败或无法检查时保留准确状态，不能将部分接入宣称为完成，也不通过放宽设计或删除用户文件消除失败。
