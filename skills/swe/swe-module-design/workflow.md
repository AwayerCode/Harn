# 模块与契约设计

## 目标

交付可供独立实现和验收的模块边界、代码映射、数据协议、质量指标与可验证条件。

## 规则

采用 YAML 模块架构的项目按[模块架构规范](../references/architecture/guide.md)执行对应职责和校验流程，替代下文相应 Markdown 架构章节的格式与命令；不重复维护层、模块、路径和依赖表格。局部交接与完整验收仍须区分，业务和接口设计职责保持不变。

遵守[按需加载与职责边界](../references/standards/loading.md)，按当前对象读取共同标准与项目契约；不加载其他专业工作流来完成本职责。

阅读[专业方法](references/professional-method.md)和[设计文档说明](references/document-format.md)。维护系统设计的模块与依赖、状态与资源所有权、关键协作路径和代码结构映射，以及接口协议；架构章节只读。共享文档的元信息与待确认问题只更新本职责内容，交付前人工逐节核对。

不改变业务含义或架构规则。契约必须评估适用的性能、可靠性、安全等质量指标，明确负载、环境、阈值和证据来源；不凭空承诺数值。测试设计负责将这些承诺转成具体验证场景。已有机器契约引用其权威定义，不复制字段。

共同要求引用[工程标准](../references/standards/engineering.md)、[执行规范](../references/standards/execution.md)及[产物规范](../references/standards/artifacts.md)。只加载本任务适用部分，不复制或自行改写标准。

## 资源

必需：业务依据、已明确的分层与依赖规则、项目标准。使用[系统设计模板](../swe-architecture-design/assets/system-design.md)的本职责章节及[协议模板](assets/interface-protocol.md)。已有项目沿用权威位置和有效约定。

## 路径

1. 按 `--kind system-design --profile architecture` 校验架构输入并审查语义；不要求模块章节预先存在。限定本次文件和章节并记录范围基线。
2. 按独立责任划模块，明确状态与资源所有权、公开能力、依赖及能力来源。
3. 在同一权威系统设计中按完整模板顺序补齐本职责章节；设计数据协议、质量指标与验收条件，映射代码位置并检查关键协作。
4. 完成后运行不带局部选项的完整检查：`<SWE目录>/bin/swe-cli design --root <项目根目录> --system-design <路径> --interface-protocol <路径>`；补做业务、架构、失败和质量承诺的语义审查。
5. 运行范围检查并核对只修改本职责章节，将契约交给专业实现与测试设计。

检查失败只修正本职责产物；依据不足或涉及契约变更时反馈对应责任方。交付实际改动、检查证据、未验证项和阻塞；提交、推送、发布另循用户授权。
