# 产物与格式契约

共同文档格式唯一来源为 `../artifact-schemas/` 中按文档类型命名的 JSON。模块的 `input-contract.json`、`artifact-contract.json` 只声明消费或产出类型及 `$ref`，`schema_version: 1` 表示当前格式集合；校验实现唯一来源为配套 Go CLI 的 `documents` 检查。

业务模型、系统设计、接口协议、交互规范、测试设计分别使用各自的当前 schema 和生产方模板。schema 是文档格式的唯一机器契约；内容不足仍由相应专业工作流判断。

目标项目保存实际业务和工程契约，Skills 仓库保存表达与检查规则。项目约定记录采用的标准及版本、路径和必要特例；若已有 API schema 或类型定义，说明它与设计文档各自的权威范围，其他地方引用，不复制字段。

从任意目录调用 `<SWE目录>/bin/swe-cli documents --root <项目根目录> --kind <类型> --file <项目文档>`。配套 CLI 是唯一校验入口，不要求运行上游工作流。退出码 0 为格式通过，1 为违规，2 为无法检查。格式通过不替代语义、实现和运行验证。

## 共同表达与检查

文档一个一级标题，二级章节按对应 schema 完整有序；细分使用三级及以下标题，前后空行、不跳级，末尾恰好一个换行。必需内容不留空，不保留模板占位符。复杂代码用声明语言并闭合的代码块；表格竖线转义。

需要文档信息的类型固定记录类型、任务、范围、依据、状态；状态为草案、待验收、已验收，只表达文档确认，不替代 Issue 任务状态。业务模型无此元信息，按其 schema 表达。

不适用章节保留标题并以“不适用：”解释具体原因，不能代替文档信息，也不能用缺少依据或未执行当作不适用。schema 检查原因非空，内容审查判断理由成立。

本地行内文件链接和普通标题锚点必须存在；校验器不检查网络链接、重复标题锚点、HTML 自定义锚点或引用式链接。机器类型定义引用准确来源，接口语义、状态和失败责任仍需内容说明。

输入类型与文档语义不足只阻塞依赖它的任务，不修改职责外的文档或 Skill 工具来获得通过。所需资料足够时直接执行，不要求先运行上游阶段。

## 架构局部产物

`--kind system-design --profile architecture` 仅检查共同 schema 指定的架构章节，适用于架构与模块设计之间交接。模块设计完成后及所有实现、验收必须使用不带 `--profile` 的完整检查；局部通过不能掩盖未完成模块或协议。

校验器只解析本次请求的 schema 类型；输入输出清单仅保留类型引用。共享对应关系检查直接使用共同校验器，不依赖设计生产方模块。
