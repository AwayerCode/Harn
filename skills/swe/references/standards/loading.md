# 按需加载与职责边界

## 加载规则

1. 接入、更新或退出任务先读 [adoption](../../adoption/SKILL.md)，再按需选领域。确定当前领域、对象、权威依据、可写范围及验收证据，选择对应领域入口；不遍历全部能力，不强制从业务模型开始。
2. 读取[领域边界](domains.md)、[执行规范](execution.md)和适用的[工程标准](engineering.md)。代码工作按需读[实现约束](implementation.md)，文档工作按需读[产物规范](artifacts.md)，不要求无关产物齐备。
3. 领域 `contract.json` 声明可引用类型与 Schema 位置，输入按任务选择；它不是执行计划，不是自动依赖安装器，也不能代替具体文件授权。
4. 领域入口提供判断与责任，详细方法按问题读取；共享规则、Schema 和工具仅来自同级 `swe` 包。项目采用约定指定表达方式、版本、路径与必要例外，不复制共享规则。

## 权威与局部产物

采用 YAML 时结构关系以 YAML 为准，设计理由与数据契约保留自己的权威来源；不要为了旧文档检查复制一套结构表格。Markdown 项目继续按其文档契约检查。两者的命令与覆盖差异见 [CLI 约定](../cli.md)。

YAML 层设计可用 `system-design validate --profile layers`，Markdown 层设计可用 `documents --kind system-design --profile architecture`。局部通过仅供交接，完整模块设计才可作为实现依据；实现验收还需要结构、依赖和行为证据。

## 职责交接

领域之间交接实际产物、规则依据、问题位置和未验证项，不靠曾经执行某个阶段证明输入有效。测试统一维护所有测试产物；代码实现可运行已有测试但不得写测试。共享文件条目及混合目录的权限遵守领域边界，检查失败不扩大范围。
