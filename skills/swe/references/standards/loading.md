# 按需加载与职责边界

## 加载规则

1. 先定位当前层、模块、操作类型、产物和验收条件，进入相应工作流；不遍历所有模块或重走全部阶段。
2. 所有专业任务遵守[工程标准](engineering.md)、[执行规范](execution.md)与[产物规范](artifacts.md)；实现和代码、UI 审查按对象读取[实现运行约束](implementation.md)。只读取相关章节、schema 类型和项目契约，不加载制定标准的方法或上游生产方工作流。
3. 输入清单声明可接受类型，不意味着每次读取所有类型。当前任务必须的依据在工作流中说明；不相关文件或 schema 缺失不阻塞独立工作。
4. 标准的规范性定义统一位于本目录和 `../artifact-schemas/`；工作流说明执行节点，模板帮助表达，不另立规则。使用标准不要求加载标准维护工作流。

## 职责与交接

总入口协调，不代替专业判断。架构设计负责分层与技术章节，模块设计负责模块与契约；共享文档按本次指定章节维护，互相只读。单元测试由任务指定的实现或测试责任方维护；独立验收测试不由实现者修改。

标准维护任务可以修改授权标准；项目设计和实现只引用共同标准，项目特殊要求写入项目工程约定，不修改包内规则。契约变更回到对应设计，缺陷回到对应实现，验收不顺手修复。只停止依赖缺口的操作。

## 局部与完整检查

架构可用 `--profile architecture` 校验自己负责章节，章节清单由 `system-design.json` 的 `profiles` 定义。无此选项时始终完整校验；局部通过不能作为实现或最终验收依据。

模块设计接收架构局部产物，在同一权威文档补齐模块章节，再通过完整格式、一致性与语义检查。专业实现与集成验收使用完整设计。架构变更后的受影响模块和契约一致性仍需完整复核。
