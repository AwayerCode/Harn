# Knowledge 文档守护

## 执行流程

1. 修改 Knowledge 文档前，先读工作空间根目录 `AGENTS.md`；知识范围以该仓库的共同约定为准，可以位于 `Knowledge/`，也可以按原有知识结构展开在根目录。
2. 判断用户是否明确要求写入。没有明确写入要求时，只分析，不改文件。
3. 判断目标类型：`NOTE.md`、总纲、模型文档、完整专题、案例文档或临时草稿。
4. 判断操作类型：格式修复、语言清理、无损整理、内容压缩、观点重写或跨文档迁移。用户只说“整理”或“优化”时，默认执行无损整理。
5. 读取或写入前，先明确用户的立场、中心问题、核心判断、实践依据和必要边界。
6. 修改前建立内容清单，记录不可丢失且具有认知价值的框架、独立判断、因果链、推导过程、方法、细节、案例、边界和重要表达。
7. 修改后逐项核对内容清单。任何项目被删除、合并或迁移，都必须能够说明去向和理由。
8. 修改后逐段执行内容价值检查。每段必须直接服务中心问题并产生认知增量；正确、完整或语义独立不构成保留理由。无认知价值内容和解释性铺垫直接删除。
9. 用户指出某种通用内容问题后，将其作为当前任务的整体检查标准，检查作用域内所有相关文档，不能只修改用户举出的例子。
10. 对已修改或已暂存的 Markdown 运行 `scripts/knowledge_lint.py`。
11. 修复 `error`；处理 `warning` 时不能以删除有效内容换取通过。
12. 完成后说明修改了哪些文件、是否删减或迁移内容、执行了哪些检查、是否还有未处理风险。

## 操作规则

根据任务类型读取对应规则：

- 查找、阅读或分析文档：读取 `references/inspect-document.md`。
- 新增或修改文档：读取 `references/write-document.md` 和 `references/markdown-format.md`。
- 删除文件：读取 `references/delete-document.md`。

`references/markdown-format.md` 是新增和修改文档时必须严格遵守的格式规范。

## 核心规则

- 没有明确写入要求时，只分析，不修改文件。
- 保留用户的认知立场和核心判断，不做中立化改写。
- 修改完整专题时默认无损整理，不压缩成总纲或摘要。
- 无认知价值内容和解释性铺垫不属于有效知识，不受无损保留约束。
- 删除文件或大幅删减有效知识必须获得明确授权。
- 修改后检查语义漂移、内容丢失、失效引用和 Markdown 格式。

## 校验

在本 Skill 目录执行：

```bash
python3 scripts/knowledge_lint.py --changed
```

提交前用 `--staged`，整体审计用 `--all`。Lint 按当前统一语法检查全部目标 Markdown；warning 也必须处理，或用具体理由说明为何不能修改对应内容。

## 完成汇报

改动 Knowledge 文档后，最终回复应包含：

- 文件：列出实际修改的文档。
- 完整性：说明是否删除、压缩或迁移内容；如有，列出去向和理由。
- 检查：说明运行了哪个 lint 命令，以及结果。
- 风险：如未运行检查、仍有未处理 warning、外部目录未修改等，明确说明。

不要把任务过程、无关背景或长篇总结写进完成汇报。
