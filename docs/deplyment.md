# Harn 分发与安装

## 目标与范围

Harn 将共同工作方法打包为可版本化的 Skill，并通过 Skill 与项目配置适配不同项目。用户临时运行 harn，安装所选 Skill 及配套 CLI；无需克隆整个源码仓，也无需全局安装。

当前 SWE 检查已迁为 Go，Node 原型与 TS 扩展执行器已移除；CLI 由构建直接放入完整平台 Skill 包，harn 只安装包内文件。本文仍包含待实施方案，项目配置初始化尚待实现；持久安装记录、项目锁与崩溃恢复已移出分发工具职责。当前可执行操作见[使用指南](usage.md)，模块边界见[系统设计](system-design.md)，版本与失败语义见[接口协议](interface-protocol.md)。本文不另行定义机器字段协议。

## 分发对象与职责

| 对象 | 内容 | 分发与使用职责 |
|---|---|---|
| harn | Go 编译的临时 Skill 分发工具 | 由启动脚本或用户临时下载；负责查找、安装和扫描本地 Skill |
| SWE Skill | 入口、专业方法、共享执行规范、标准与 schema | 用户选择安装的能力；指导 Agent 完成独立任务 |
| swe-cli | Go 编译的独立校验二进制 | 直接包含在 SWE 平台 Skill 包内；执行单次确定性校验，不承担安装管理 |
| 项目定制 | 项目配置、契约和自定义方法 | 由项目维护，独立于托管的通用资源，更新不覆盖 |
| Agent 接入文件 | 原生 Skill 入口或项目约定中的引用 | 让 Agent 发现并加载已安装 SWE；不复制另一套方法 |

## 临时运行 harn

1. 在业务项目根目录运行启动器，识别操作系统与 CPU 架构，选择 harn 发行版本。
2. 将对应二进制及摘要下载到系统临时目录并校验。
3. 执行指定分发命令，无命令时执行 search；退出后清理临时二进制。

macOS/Linux 使用 install.sh，参数 `--` 后传入 harn 命令；脚本不再提供 bin-dir 或安装到项目。Windows 使用项目外临时目录中的已校验 harn.exe。当前新行为需源码构建，发行资产发布后才可通过启动器使用。

harn 的发行版本与 Skill 的资源版本分别选择。下载 harn 不表示 SWE 或 swe-cli 已安装，也不产生项目管理目录。

## 安装 Skill 与配套 CLI

### 能力发现与版本选择

用户通过 harn search 查找能力，再使用 install 指定来源、版本和资源路径。当前命令只支持选择 Skill 目录；目标方案保持“选择完整 SWE 平台包即取得其配套工具”的体验，不要求用户分别查找 swe-cli 资产。

源码当前路径为 `skills/swe`；旧版 `v0.2.1` 的路径仍是 `Skills/swe`。安装路径必须与所选版本的源码目录一致，不能把旧版标签与新版小写路径混用。

### 配套资源清单

仓库只发布 Harn，发行目录包含 harn 与六个平台 SWE Skill 包。平台包在构建阶段加入 CLI 和本地 runtime.json；清单只有名称、版本与本平台摘要，不含下载 URL，不参与 harn 的安装决策。SWE 源码归档不含编译产物，不能作为完整 CLI 套件安装。

构建与安装分工：

1. SWE 打包脚本编译六平台 CLI，将各自二进制放入对应包的 bin/，生成本地摘要清单。
2. Harn 发行脚本将 harn 与六个完整 Skill 包汇总，生成统一 SHA256SUMS；不建立独立 swe-cli Release。
3. 用户选择本机平台 Skill 包，harn 下载一次归档，检查入口与路径后将包内文件安装到空目标。
4. 已有目录拒绝覆盖，普通错误清理本次创建目录；运行时的版本与摘要由包内 swe-cli 自检。

harn 不解析任何 CLI 下载清单。无需 CLI 的 Skill 可安装源码归档，需要 CLI 的 Skill 应由发布者提供完整平台包。

### 项目内布局

当前项目只保存 Skill 及配套 CLI；Windows 可执行文件增加 `.exe`：

```plaintext
.agents/
  skills/
    swe/
      SKILL.md
      references/
      runtime.json
      bin/
        swe-cli
```

所有专业方法与配套 CLI 都位于所属 Skill 内，不另建下载记录、项目锁或安装数据库。Skill 文本可随 Git 保存；本平台 bin/ 与生成的 runtime.json 一起忽略。跨平台克隆后，安装相同发行版本的本机平台包到临时项目，对比 Skill 文本后一起补入 bin/ 和 runtime.json。

## Agent 接入与日常使用

当前源码将 Skill 直接安装到 `.agents/skills/`，支持该目录的 Agent 使用原生发现机制，不再要求通过 AGENTS.md 引用入口。harn 不改写项目已有指令；其他宿主可显式读取入口，适配与实际发现行为仍需按宿主验证。

日常任务在 Agent 会话中提出。Agent 读取 SWE，加载项目配置与相关契约，再按共享执行规范完成执行、校验、反馈和修正。swe-cli 的安装路径由配套信息定位，不依赖全局命令；CLI 不接管 Agent，也不启动任务分发循环。

安装后的验收应分别确认资源完整、CLI 可运行、Agent 能发现入口、项目配置确实被读取。文件存在不能单独证明接入生效。

## 按项目定制

通用 Skill 保存共同方法；项目配置选择适用标准、契约路径、目录边界、检查集合与规则参数。自定义方法由项目约定或项目 Skill 承载，放在托管资源外，避免升级覆盖。项目已有测试、lint、构建和专属检查由 Agent 按 Skill 调用，不接入 CLI 插件系统；稳定通用检查通过 Go 核心迭代交付。

项目配置文件位置与机器格式在实施前确定，不在本文预造可执行命令。配置初始化只建立必要入口，不生成无关业务设计。必需检查由采用的标准与任务契约确定，项目定制不能偷偷关闭它们；需要改变标准时走明确的设计变更。

## 换版、补装与移除

harn 保留 search、install、list、version。list 扫描原生 Skill 目录；不提供 update、status、remove，不推断来源、版本或本地修改。

换版先向临时项目安装指定版本，再核对差异和自有内容，由维护者显式替换完整 Skill。补装从相同版本的本机平台包复制 bin/ 与对应 runtime.json。移除先备份自有内容，再删除整个 Skill 目录；CLI 随 Skill 移除。完整安装后，核心可离线运行，项目测试的外部依赖另行说明。

已有目录即使残缺也拒绝覆盖。安装没有持久事务或项目锁，不承诺崩溃自动恢复；异常终止后人工检查并清理本次不完整目录，再重新安装。不要在安装过程中编辑或执行目标 Skill。

## 发布与验收

Harn 源码在本仓维护，本地运行测试与构建，手动上传 GitHub Releases。harn 和 swe-cli 均采用 Go；仓库只创建 Harn Release，swe-cli 在构建时进入 Skill 包，不发布独立二进制。

交付目标覆盖 macOS、Linux、Windows 的 amd64/arm64。六平台构建与实际运行验证分开记录；SWE 提供六平台 Skill 打包脚本；最低系统要求及各平台实际运行仍需发行验收。

发布前验证：无系统 Go/Node/TS/Python 的环境能运行 SWE 核心；仅下载并安装所选平台 Skill 包；归档错误不发布入口，包内 CLI 版本或摘要不符时拒绝运行；已有目录拒绝覆盖；普通错误清理本次创建目录；临时安装与配套核对可用于跨平台补装；项目定制由维护者保留；Agent 能实际加载入口并完成一次任务内校验闭环。

## 当前配套安装

SWE 平台包包含完整方法资源、bin/swe-cli 和生成的 runtime.json。清单的 assets 仅保存本平台 SHA256，不含外部地址；CLI 启动时校验自身。harn 不读取清单、不补装缺失 CLI，也不根据平台重新下载文件。

验证应覆盖实际 Skill 包安装后可离线运行、包摘要与可执行文件摘要一致、安装仅请求一个归档、Windows 包携带 .exe。六平台构建通过不代表各平台已实际运行验收。
