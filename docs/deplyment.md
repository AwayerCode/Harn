# Harn 分发与安装

## 目标与范围

Harn 将共同工作方法打包为可版本化的 Skill，并通过Skill 与项目配置适配不同项目。用户先安装项目内的 harn，再由 harn 安装所选 Skill 及配套 CLI；无需克隆整个源码仓，也无需全局安装。

当前 SWE 检查已迁为 Go，Node 原型与 TS 扩展执行器已移除；harn 支持按 runtime.json 下载并校验配套 CLI。本文仍包含待实施方案，自动 Agent 接入、项目配置初始化、崩溃恢复与安装读锁尚待实现。当前可执行操作见根目录 [HARN.md](../HARN.md)，模块边界见[系统设计](system-design.md)，版本与失败语义见[接口协议](interface-protocol.md)。本文不另行定义机器字段协议。

## 分发对象与职责

| 对象 | 内容 | 分发与使用职责 |
|---|---|---|
| harn | Go 编译的项目内资源管理工具 | 首次由安装脚本或用户手动下载；负责后续能力安装、更新、状态检查和移除 |
| SWE Skill | 入口、专业方法、共享执行规范、标准与 schema | 用户选择安装的能力；指导 Agent 完成独立任务 |
| swe-cli | Go 编译的独立校验二进制 | 作为 SWE 的配套资产由 harn 下载；执行单次确定性校验，不承担安装管理 |
| 项目定制 | 项目配置、契约和自定义方法 | 由项目维护，独立于托管的通用资源，更新不覆盖 |
| Agent 接入文件 | 原生 Skill 入口或项目约定中的引用 | 让 Agent 发现并加载已安装 SWE；不复制另一套方法 |

## 首次下载安装 harn

1. 在业务项目根目录运行安装器；识别操作系统与 CPU 架构，解析所选发行版本。
2. 从 GitHub Releases 获取对应 harn 二进制及摘要，完成完整性校验。
3. 将可执行文件安装到 `.harness/bin/harn`，Windows 使用 `harn.exe`，无需配置全局 PATH。
4. 执行 version 确认入口可运行，再安装所需能力。首次引导不自动下载所有 Skills。

macOS/Linux 已有 Shell 安装器，Windows 当前通过 Releases 手动下载，PowerShell 自动安装是待补能力。手动安装与脚本安装应使用相同发行物、校验规则和项目布局。

首次下载 harn 与安装 SWE 是两个动作：harn 是管理工具，下载它不表示 SWE 或 swe-cli 已安装。harn 自身升级需通过安装器或手动替换已校验产物；现有资源 update 命令不应被解释为 harn 自更新。

## 安装 Skill 与配套 CLI

### 能力发现与版本选择

用户通过 harn search 查找能力，再使用 install 指定来源、版本和资源路径。当前命令支持按路径下载资源；目标方案保持“选择 SWE 即取得其配套工具”的体验，不要求用户分别查找 swe-cli 资产。

源码当前路径为 `skills/swe`；旧版 `v0.2.1` 的路径仍是 `Skills/swe`。安装路径必须与所选版本的源码目录一致，不能把旧版标签与新版小写路径混用。

### 配套资源清单

发行清单声明 Skill 修订、配套 CLI 版本、支持平台、资产位置与摘要，以及规则和接口的兼容关系。清单是 harn 的安装输入，不是让 Agent 自行猜测下载地址的提示词。具体字段沿用接口协议，清单文件名和格式在实施时冻结。

安装 SWE 时，harn 依次完成：

1. 解析指定版本，读取所选能力的发行清单。
2. 下载该能力的方法与标准，并选择本机平台的 swe-cli。
3. 校验摘要与配套版本，将全部文件暂存；缺少资产、平台不支持或版本不兼容时停止，不报告安装成功。
4. 在项目锁保护下提交安装与记录；中途失败按接口协议恢复，不能留下被当作可用的新旧混合版本。
5. 返回实际入口、版本、安装路径和接入说明。核心缺失时明确提示修复，不回退旧 Python 实现。

首版只解决明确声明的配套资产，不扩展成任意 CLI 的通用包管理器。Skill 不依赖二进制时可独立安装；声明必需 CLI 的 Skill 必须完整配套才算可用。

### 项目内布局

以下是目标布局，Go swe-cli 已支持按 Skill 清单安装，项目配置和恢复标记仍待实现；Windows 可执行文件增加 `.exe`：

```plaintext
.harness/
  bin/
    harn
  skills/
    swe/
      SKILL.md
      references/
      bin/
        swe-cli
  downloads.json
```

实际专业 workflow 等资源保留各自目录，图中只展示分发边界。downloads.json 当前保存资源下载记录，配套版本与本机安装状态需要显式演进格式，不能假设现有版本已支持。

二进制和临时锁不提交业务项目 Git；Skill 及可移植版本绑定可随项目保存。目标布局需要同时忽略 `.harness/bin/` 和 `.harness/skills/swe/bin/`。项目克隆到另一平台后，由 harn 按相同绑定补装本机二进制，不自动切换最新版本。

## Agent 接入与日常使用

下载完成后还要让 Agent 能发现入口。当前 Harn 通过用户明确指令或手工维护的 AGENTS.md 引用 SWE；自动接入是新增能力，不是现有 install 的行为。

目标接入流程是用户选择所用 Agent，harn 在明确授权下创建或更新其支持的入口，指向项目内 SWE。优先使用宿主原生 Skill 机制，并保留项目约定接入方式。只维护自身声明的文件或区域，不覆盖项目已有指令；具体宿主目录与加载行为通过适配验证，不假设所有 Agent 相同。

日常任务在 Agent 会话中提出。Agent 读取 SWE，加载项目配置与相关契约，再按共享执行规范完成执行、校验、反馈和修正。swe-cli 的安装路径由配套信息定位，不依赖全局命令；CLI 不接管 Agent，也不启动任务分发循环。

安装后的验收应分别确认资源完整、CLI 可运行、Agent 能发现入口、项目配置确实被读取。文件存在不能单独证明接入生效。

## 按项目定制

通用 Skill 保存共同方法；项目配置选择适用标准、契约路径、目录边界、检查集合与规则参数。自定义方法由项目约定或项目 Skill 承载，放在托管资源外，避免升级覆盖。项目已有测试、lint、构建和专属检查由 Agent 按 Skill 调用，不接入 CLI 插件系统；稳定通用检查通过 Go 核心迭代交付。

项目配置文件位置与机器格式在实施前确定，不在本文预造可执行命令。配置初始化只建立必要入口，不生成无关业务设计。必需检查由采用的标准与任务契约确定，项目定制不能偷偷关闭它们；需要改变标准时走明确的设计变更。

## 更新、修复与卸载

| 操作 | 目标行为 |
|---|---|
| 更新 | 用户明确选择版本，预演并检查本地修改，配套更新 Skill 与 CLI；保留项目定制 |
| 修复 | 针对缺失或损坏文件恢复绑定版本；若存在正常本地修改，先区分原因，不静默覆盖 |
| 卸载 | 移除选定能力及其专属配套资产，处理工具维护的 Agent 入口；保留项目业务产物和自定义内容 |
| 离线使用 | 安装完整后，核心可离线运行；项目测试所需外部服务依赖另行说明 |

当前 harn 已有 install、update、remove、list、status、search；配套二进制恢复和 Agent 接入生命周期仍待实现。缺失核心不能被 status 或 Agent 解释为检查通过。

## 发布与验收

Harn 源码在本仓维护，本地运行测试与构建，手动上传 GitHub Releases。harn 和 swe-cli 均采用 Go，按配套版本关系交付；不要求两者版本号完全相同。

交付目标覆盖 macOS、Linux、Windows 的 amd64/arm64。六平台构建与实际运行验证分开记录；Go swe-cli 提供六平台构建脚本；最低系统要求及各平台实际运行仍需发行验收。

发布前验证：无系统 Go/Node/TS/Python 的环境能运行 SWE 核心；只下载所选资源和匹配平台资产；校验失败不启用安装；更新故障可恢复；克隆后按绑定补装；项目定制保留；Agent 能实际加载入口并完成一次任务内校验闭环。

## 当前配套安装

SWE 的 runtime.json 声明 schema_version、工具 name/version，以及按 os/arch 索引的 url/sha256。harn 在源码资源暂存区下载所选平台二进制，验证后写入 Skill 的 bin 目录，复用现有资源提交与回滚。二进制纳入 downloads.json 的文件摘要，修改后更新拒绝覆盖；资源下载失败、平台缺失或摘要错误不会启用新资源。配套文件不跨 Skill 共享所有权。

当前实现尚不提供进程崩溃后的持久化事务恢复或检查读锁，不能等同于前文目标方案的完整发行验收。清单绑定的 0.3.0-alpha.1 资产尚需另行发布，不能回退到旧预发布二进制。
