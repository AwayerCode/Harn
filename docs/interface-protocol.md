# 接口协议

## 文档信息

| 字段 | 值 |
|---|---|
| 类型 | interface-protocol |
| 任务 | Harn 独立 SWE 任务的执行与校验边界 |
| 范围 | Skill 接入与交接、单次校验、工作区、扩展和配套安装 |
| 依据 | [系统设计](system-design.md)、[Issue #6](https://github.com/AwayerCode/Harn/issues/6)、[现行执行规范](../skills/swe/references/standards/execution.md) |
| 状态 | 草案 |

## 范围与权威来源

本协议定义目标接口，尚未实现的命令不得当作当前用法。模块与职责以系统设计为准；现有业务项目文档格式的权威仍是 `skills/swe/references/artifact-schemas/`，不在这里复制。新运行协议暂以本文为权威，实施时提取机器 schema 并改为引用，不能平行维护两套字段。

Agent 是外部调用者，Skill 是运行于 Agent 上下文中的方法，不是服务端。Skill 对流程负责，CLI 对其实际接受的单次检查负责；二者的结果不互相替代。分发和持久化协议只涉及工具安装，不管理业务任务队列。

## 公共数据

### 任务上下文与证据

| 数据 | 必需语义 | 所有权与约束 |
|---|---|---|
| taskId、mode | 当前任务标识；mode 为 design、implement、test 或 review | Agent 按 skill-flow 维护；不用于自动派发 |
| goal、authority、allowedWrites、completionCriteria | 目标、权威依据、允许修改对象和完成条件 | 以用户及项目契约为准，不能因检查失败自行改写 |
| requiredChecks、externalEvidence | 必需核心/扩展集合，以及项目测试、专业判断等证据要求 | Skill 与任务确定；CLI 不能推断未提交的业务要求 |
| round、limits、baselineRef | 当前轮次、已约定上限、原范围基线位置或只读指纹 | 业务写入前固定基线；恢复不能重建以掩盖历史修改 |
| progress、blockers、nextAction | 实际进度、阻塞与恢复动作 | 默认在会话；只读审查不创建状态文件 |

任务完成状态与检查状态分开。Agent 的终态是 completed、blocked、stalled、limit-reached 或 cancelled；blocked 带需要决策或环境/工具故障的原因。review 的 completed 表示审查覆盖和证据交付完成，可以包含缺陷。CLI 只输出检查结果，不签发 task completed。

### 单次请求与结果

设计中的汇总入口为 `swe-cli check --request <JSON文件或-> --format json`，`-` 从 stdin 读取，便于只读调用不产生请求文件。help/version 不依赖项目；检查明确提供 projectRoot 和资源定位信息，不靠 cwd 猜测。

| 数据 | 内容与不变量 |
|---|---|
| request | protocolVersion、taskId、round、mode、projectRoot、检查输入与依据、必需检查集合、明确扩展配置、baselineRef（适用时） |
| identity | CLI 生成的 runId、输入摘要、规则及核心版本、扩展接口版本与扩展摘要；taskId/round 是调用者标签，不是已验证历史 |
| checks | 每项具有 checkId、source、required、status、diagnostics、coverage 与 evidence；source 区分 core/extension |
| diagnostic | 稳定 ruleId、问题类型、可定位对象、说明和证据引用；同类问题可跨轮比较，不以自由文本作为唯一标识 |
| status | passed、failed、unavailable、not-run；不适用项在计划中明确排除并说明依据，不能事后把失败改为不适用 |
| summary | 只归并当前请求范围，不代表产品整体完成；保留所有核心原始项，扩展展示不覆盖它 |

退出码保持 0/1/2：全部必需项 passed 为 0；无不可检查项但存在必需 failed 为 1；任一必需项 unavailable/not-run，或请求/版本/运行错误，为 2。同时存在违规和工具错误时返回 2，但保留违规诊断。可选项失败作为显式警告；Skill 仍可据其影响阻止交付。未知必需 checkId、缺失工具和无效扩展输出均不能默认为通过。

输入摘要覆盖检查所读取的文件内容、契约、配置、版本和适用 Git 状态；保存前后状态以发现读取期间变化。发生变化时相关检查为 unavailable，不宣称原子快照；不能阻止并发编辑。报告说明摘要覆盖范围，外部服务及项目运行测试不能仅靠文件摘要证明有效。首版交付前重新运行全部必需机器检查，不实现跨轮结果缓存复用。

### 扩展与配套版本

扩展配置明确 id、来源路径、内容摘要、接口版本、用途、required、timeoutMs、输入与允许副作用。首版无自动扫描执行、联网装依赖或任意 npm 导入。随包扩展路径相对 SWE 根，项目扩展路径相对明确 projectRoot；解析为实际路径并核对授权范围，路径穿越与符号链接不得绕过范围约束。

扩展输出为版本化结果对象，包含自身 status、diagnostics 和带来源的 data/evidence；扩展不能写 core 命名空间或任务完成状态。采集结果只作为已声明的输入，不能覆盖核心直接读取的权威数据；报告加工只能生成非权威视图。扩展执行不是安全沙箱，任意副作用仍需可信代码和授权。

发行绑定包含资源修订、核心版本、协议版本、扩展接口版本、随包扩展及规则摘要、平台、发行资产地址与 SHA-256。平台无对应资产时拒绝安装，不下载其他架构尝试。平台无关的资源绑定可随项目保存，本机平台安装状态与二进制分开；克隆后按同一绑定补装，不能改为 latest。

## 协议定义

### 进入独立任务

| 字段 | 值 |
|---|---|
| 协议标识 | skill.enter |
| 提供方 | skill-flow |
| 调用方 | 外部:Agent |
| 边界类型 | 外部 |
| 交互方式 | Skill 文件与会话 |
| 输入与输出 | 输入任务指令、项目约定和已安装 SWE；输出所选专业方法与任务上下文。 |
| 数据语义与前置条件 | Agent 能读取入口；相关任务依据可定位。只检查当前专业方法需要的输入，不把全部文档齐备作为门槛。 |
| 状态变化与副作用 | 只在会话建立目标、范围与完成条件；尚不写业务文件，不自动修改项目接入规则。 |
| 失败语义与责任 | 依据缺失仅阻塞相关动作；核心缺失先报告补装要求，不能把不可检查当通过。 |
| 交互约束 | 先确定范围和检查集合再写入；任务 mode 决定修改权限。时间限制以用户约定为准，无服务可用性承诺。 |
| 演进规则 | 方法流程可独立迭代；涉及检查协议或标准变化必须绑定兼容版本，不能静默降低要求。 |
| 验证依据 | 以有完整输入和有局部缺口的任务对话验证按需加载、职责边界及未验证说明。 |

### 单次确定性校验

| 字段 | 值 |
|---|---|
| 协议标识 | check.run |
| 提供方 | check-entry |
| 调用方 | skill-flow、外部:Agent |
| 边界类型 | 外部 |
| 交互方式 | 本地 CLI 与 JSON |
| 输入与输出 | 输入公共数据中的 request；输出 identity、checks、summary 与退出码。支持 stdin，stdout 仅有一个完整 JSON 结果。 |
| 数据语义与前置条件 | 配套版本与资源完整性已核验，检查集合与输入可解析；必需项不能被项目配置禁用。非法参数与协议不兼容返回 2。 |
| 状态变化与副作用 | 默认只读工作区，结果只输出；不修复业务产物，不变更任务轮次或运行下一轮。 |
| 失败语义与责任 | 按公共状态及退出码处理；无输出、截断输出、进程被终止都属于不可检查，调用 Agent 负责报告或授权内恢复。 |
| 交互约束 | 单次调用有明确顺序：验证请求、读取输入、核心检查、所选扩展、归并。查询可重复但新 runId，不承诺输入变化后的同一结果；读取期间变化不报通过。 |
| 演进规则 | 主协议版本不兼容拒绝；已定义字段不静默改义。新增诊断保持 ruleId 稳定，语义变更更新规则版本。 |
| 验证依据 | 同一组新旧正反例对照；必需失败不能被扩展覆盖，缺失检查返回 2；报告能关联最终输入。 |

### 工作区读取与范围基线

| 字段 | 值 |
|---|---|
| 协议标识 | workspace.read |
| 提供方 | workspace |
| 调用方 | check-entry |
| 边界类型 | 模块 |
| 交互方式 | 注入的本地接口 |
| 输入与输出 | 输入 projectRoot、明确文件与 Git 读取要求；输出内容、状态摘要、覆盖限制或读取错误。scope snapshot 返回基线引用；readonly 返回指纹。 |
| 数据语义与前置条件 | Git 根、允许路径和项目外新基线路径明确；路径按实际文件系统语义处理。父仓授权不跨入子模块。 |
| 状态变化与副作用 | 读取不写业务文件；snapshot 仅显式创建全新项目外基线，不覆盖已有基线。check/readonly 只读。 |
| 失败语义与责任 | Git 缺失、超时、权限或读取错误返回不可检查；不自动拉取或初始化子模块，不通过重新基线消除差异。 |
| 交互约束 | 沿用现有范围覆盖：跟踪、非忽略、明确允许的忽略产物与子模块状态；不覆盖全部忽略项、.git、项目外或改后恢复动作。Git 单次最多等待 10 秒，沿用现行规范。 |
| 演进规则 | 基线格式版本化；不兼容旧基线时明确拒绝，迁移不能改变原始内容语义。 |
| 验证依据 | 用现有范围检查夹具验证删除、权限、子模块和不可检查情况；Windows 实际验证路径语义与可执行权限差异。 |

### 指定外围 TS 执行

| 字段 | 值 |
|---|---|
| 协议标识 | extension.run |
| 提供方 | extension-host |
| 调用方 | check-entry |
| 边界类型 | 模块 |
| 交互方式 | 子进程 JSON 输入输出 |
| 输入与输出 | 输入公共扩展配置和版本化上下文；输出扩展独立结果。日志走 stderr，不混入 JSON。 |
| 数据语义与前置条件 | 扩展明确启用，接口匹配且代码摘要可记录；所需运行能力已在发行包内。Review 仅允许运行已审查为无写入的扩展，否则不执行并说明。 |
| 状态变化与副作用 | 子进程只做声明用途；核心父进程不提供可修改原始诊断的接口。执行所需内存随进程结束释放。 |
| 失败语义与责任 | 超时、崩溃、非法输出和版本不兼容为 unavailable；必需扩展影响整体退出码。取消后终止子进程并回收资源，不留后台继续运行。 |
| 交互约束 | 每项配置必须有正 timeoutMs；值按项目负载在调用前指定，不臆造统一性能 SLA。首版顺序运行，禁止扩展相互依赖执行顺序产生隐式共享状态。 |
| 演进规则 | 独立扩展接口版本；只承诺已声明 TS 子集和模块白名单，不承诺任意 tsconfig 或第三方依赖。 |
| 验证依据 | 发行二进制在无系统运行时环境执行代表性 TS；覆盖异常、超时、输出污染和取消；证明不能通过正常输出协议改写核心失败。 |

### 任务退出与按需恢复交接

| 字段 | 值 |
|---|---|
| 协议标识 | task.handoff |
| 提供方 | skill-flow |
| 调用方 | 外部:Agent |
| 边界类型 | 外部 |
| 交互方式 | 会话交接摘要 |
| 输入与输出 | 输入当前上下文、结果和退出原因；输出终态、实际改动、证据、剩余问题与恢复条件。 |
| 数据语义与前置条件 | completed 必须满足 mode 对应完成条件；review 可带缺陷完成。blocked/stalled 等不得呈现为成功。 |
| 状态变化与副作用 | 默认仅回复，不写文件、不派发下一任务。用户明确要求保存时才将摘要写入授权位置，不能违反只读任务限制。 |
| 失败语义与责任 | 上下文丢失、基线缺失或版本变化由恢复 Agent 明确报告；不能用新基线证明旧修改未越界。 |
| 交互约束 | 恢复需核对当前工作区、版本和既有范围，保留轮次和失败历史；新上限须明确约定。新证据与旧证据分别记录。 |
| 演进规则 | 交接是人和 Agent 可读摘要，首版不承诺长期数据库兼容；记录所用协议与工具版本供恢复判断。 |
| 验证依据 | 用同一独立任务验证中断后继续、旧证据过期、需要决策和只读审查交付，不涉及任务派发。 |

### 获取固定版本配套发行物

|---|---|
| 协议标识 | release.fetch |
| 提供方 | delivery-io |
| 调用方 | distribution |
| 边界类型 | 模块 |
| 交互方式 | 下载接口 |
| 输入与输出 | 输入来源、固定修订、所选资源和当前平台；输出暂存资源、平台二进制与绑定清单。 |
| 数据语义与前置条件 | 保留当前来源限制和明确选择资源；branch 解析为不可变修订并记录。资源必须提供可绑定的发行物，缺失则拒绝二进制配套安装。 |
| 状态变化与副作用 | 仅写暂存区，不提前改动已安装资源，不下载整仓到业务工作区。下载原始归档的现有行为不等于业务项目复制全仓。 |
| 失败语义与责任 | 网络、摘要、平台或配套版本错误在提交前失败，旧版本仍可使用；清理失败说明遗留位置。 |
| 交互约束 | 受控下载与解包，不接受越界归档路径；单次超时沿用 harn 实现并在接口冻结时记录，不能无限重试或切换 latest。 |
| 演进规则 | 发行绑定格式版本化；旧发行物可继续按旧资源流程处理，但不能冒充含核心的新套件。 |
| 验证依据 | 校验错误摘要、缺平台、丢失资产与离线已安装使用；确保未选资源不写入项目。 |

### 配套提交与恢复记录

| 字段 | 值 |
|---|---|
| 协议标识 | install.commit |
| 提供方 | delivery-io |
| 调用方 | distribution |
| 边界类型 | 模块 |
| 交互方式 | 本地事务接口 |
| 输入与输出 | 输入已验证暂存物、旧记录与变更计划；输出提交后的绑定或可恢复失败状态。 |
| 数据语义与前置条件 | 获取项目写锁，核对当前安装未被其他进程更改；托管文件有本地修改时停止，不覆盖项目自定义扩展。 |
| 状态变化与副作用 | 先记录事务与不可用标记，再替换所选资源和本机二进制，最后提交绑定记录并清标记。失败回滚，保留必要恢复数据。 |
| 失败语义与责任 | 提交失败且回滚成功保留旧版本；崩溃或回滚失败保持不可用标记并报告恢复动作，不能宣称旧版本正常。 |
| 交互约束 | 检查持读锁、更新持写锁；检查只打开安装时已创建的锁资源，不创建或改写锁文件，缺失则返回不可检查。多文件替换不是文件系统原子事务。读者发现未完成事务拒绝使用，恢复按日志完成或回退同一版本。 |
| 演进规则 | downloads.json v1 到配套记录需显式迁移与备份；新旧客户端不兼容时拒绝。修复不静默覆盖本地改动，不改变锁定版本。 |
| 验证依据 | 在提交步骤间注入故障并重启；验证无可用混搭、旧文件与记录一致、自定义扩展保留和同版本恢复。 |

### 安装记录持久化

| 字段 | 值 |
|---|---|
| 协议标识 | install.record |
| 提供方 | 存储:项目安装记录 |
| 调用方 | delivery-io |
| 边界类型 | 持久化 |
| 交互方式 | 版本化 JSON 与事务日志 |
| 输入与输出 | 读取或写入资源绑定、本机平台安装信息及未完成事务；这些记录不是业务任务状态。 |
| 数据语义与前置条件 | 路径属于当前项目安装器管理范围，格式合法且可识别；对记录损坏不得用空记录替代。 |
| 状态变化与副作用 | delivery-io 在锁内写临时文件并提交记录；资源绑定与事务状态以明确提交点关联，避免只更新一半。 |
| 失败语义与责任 | 写失败或格式损坏时返回不可用并保留备份；distribution 决定恢复，不能猜测成功或删除恢复依据。 |
